# Changelog

Every notable change to the 3ops Discovery specification is recorded in
this file. Russian original: [CHANGELOG.ru.md](CHANGELOG.ru.md).

## 0.2.0 -- Draft

- Docker stdout/stderr is collected by default for every container.
- `ru.3ops.discovery.logs.enabled=false` acts as the explicit opt-out.
- `ru.3ops.discovery.logs.profile` now names a predefined, versioned pipeline profile.
- Profiles of the form `json,logfmt,raw` are forbidden: a label is not a language for describing stages.
- `raw` is the implicit fallback of any profile whenever a parsing stage fails to read the line.
- Added the base profiles `raw-v1`, `generic-json-v1`, `generic-logfmt-v1`, `mixed-v1`.
- Added versioning rules for log pipelines.
- Free-form `interval`/`timeout` values in labels were replaced by the versioned allowlist profiles `metrics.profile`, `database.profile`, `blackbox.profile`.
- The version-in-the-name requirement was extended to all profiles, not just log profiles.
- The secret contract was generalized to the `snmp` and `ipmi` domains (per-domain secret file suffixes).
- Documented the exemption of the `logs` domain from the `ru.3ops.discovery.enabled` requirement.
- The reference Alloy configuration moved into the `alloy/` directory (files with numeric prefixes; the single integration point with the backend is [`090_outputs.alloy`](alloy/090_outputs.alloy)).
- Defined the `RU_3OPS_DISCOVERY_*` environment variable contract for deployment-specific parameters of the reference configuration.
- Fields extracted from log content go to structured metadata only, never to stream labels.
- The `secret-id` space is documented as a single trust domain of the host; binding a secret to a container identity is declared out of scope.
- Added section [13.5](docs/manifest.md#135-trust-in-labels) on the boundaries of trust in labels.
- The reference configuration implements the `path`/`scheme`/`profile` relabel validations and collapses the port fan-out for metrics and database.
- The database domain was extended to the types `mysql`/`mariadb`, `redis`, `mongodb`; the series of every exporter carry provenance labels (`environment`/`team`/`container`/`compose_*`/`collector`, plus synthesized `job`/`instance`).
- For redis the secret format is `host:port` in `.dsn` plus the password in a separate `<secret-id>.redispass` file (the `redis_addr` argument does not accept a secret).
- Added the multiline log profiles `python-stacktrace-v1` and `java-stacktrace-v1`: multiline tracebacks are glued into a single record.
- Introduced the `alloy-optional/` overlay directory and its first opt-in file [`060_otel.alloy`](alloy-optional/060_otel.alloy) (OTLP receiver: metrics into `prometheus.remote_write`, logs into `loki.write` through an allowlist processor).
- Documented the customization model: base extension points (section [14.4](docs/manifest.md#144-extension-points)), optional files ([14.5](docs/manifest.md#145-optional-files)), conventions against name collisions.
- Added tables of standard database ports ([10.2](docs/manifest.md#102-domain-database)) and of secret file formats per type ([9](docs/manifest.md#9-secret-contract)); recorded the provenance exemption of the OTLP path.
- Clarified that `database.type` denotes the wire protocol rather than the vendor: protocol-compatible builds (Percona Server for MySQL/MongoDB, XtraDB Cluster) are labelled with the base type `mysql`/`mongodb` without a type of their own.
- Added the optional host metrics file [`070_host-metrics.alloy`](alloy-optional/070_host-metrics.alloy) (`prometheus.exporter.unix`, `node_*` series); the rootfs/procfs/sysfs paths are parameterized by `RU_3OPS_DISCOVERY_HOST_ROOTFS_PATH`/`_PROCFS_PATH`/`_SYSFS_PATH`.
- Added the optional host logs file [`080_host-logs.alloy`](alloy-optional/080_host-logs.alloy) (`loki.source.journal` from the systemd journal into `loki.write`) with the static labels `host`/`collector`/`source`.
- Implemented the blackbox domain ([`035_blackbox.alloy`](alloy/035_blackbox.alloy)): HTTP probes driven by the `ru.3ops.discovery.blackbox.*` Docker labels through `prometheus.exporter.blackbox` (reference module `http_2xx`, profile `normal-v1`).
- The snmp domain ([8.5](docs/manifest.md#85-snmp-profiles)/[10.6](docs/manifest.md#106-domain-snmp)/[10.6.1](docs/manifest.md#1061-snmp-auth)/[14.5](docs/manifest.md#145-optional-files)): a file-based device provider, the v2c/v3 (authPriv) auth model, the opt-in overlay [`037_snmp.alloy`](alloy-optional/037_snmp.alloy), static gates and e2e against a live Net-SNMP agent.
- Clarified the ipmi domain ([10.7](docs/manifest.md#107-domain-ipmi)): Alloy has no native IPMI component, so the domain is reformulated as a special case of `metrics` -- scraping the Prometheus endpoint of an external `ipmi_exporter`; the labels and the `.ipmi` secret suffix are kept (the contract semantics did not change).
- Added the optional per-container metrics file [`075_container-metrics.alloy`](alloy-optional/075_container-metrics.alloy) (`prometheus.exporter.cadvisor`, series `container_cpu_*`/`container_memory_*`/`container_network_*`): the Docker API through the socket proxy (reusing `RU_3OPS_DISCOVERY_DOCKER_HOST`), provenance per [6.1](docs/manifest.md#61-labels-added-by-alloy) built from allowlisted container labels (`name` becomes `container`, raw `container_label_*` are dropped), root cgroup statistics disabled; requires the host cgroup namespace (`cgroup: host`, a privileged overlay per [14.3](docs/manifest.md#143-customizing-the-reference-configuration)).
- The reference configuration implements every base scrape profile of [8.2](docs/manifest.md#82-scrape-profiles) (`fast-v1`/`normal-v1`/`slow-v1`) for the metrics and blackbox domains: a shared relabel carries validation and provenance, a thin filter-plus-scrape pair per profile carries the routing; the names of profile components are derived from the full profile name.
- The blackbox domain gained the `tcp_connect` and `icmp` modules with per-component composition of the probe target (URL / `host:port` / bare host); probe series gained a `module` label; ICMP probes work without extra container privileges, and the way out for hardened environments is documented.
- Added the `tls_connect` module -- all four promised probe families (HTTP, TCP, ICMP, TLS) are now shipped by the reference; the module checks the TLS handshake and reports certificate expiry metrics, while trust chain verification is documented as an environment customization (`ca_file`).
- Implemented the database profiles of [8.4](docs/manifest.md#84-database-profiles) (`basic-v1`/`standard-v1`/`extended-v1`): a profile governs the collection volume of the exporter (the set of collectors) rather than the scrape cadence; `standard-v1` matches the exporter defaults, a value outside the allowlist drops the target (fail-closed); the mapping of profiles onto collectors per database type is documented in [8.4](docs/manifest.md#84-database-profiles).
- The snmp module allowlist ([10.6](docs/manifest.md#106-domain-snmp)) gained `system` (identity and uptime of agentless devices: `sysUpTime`, `sysName`); one device file entry means one module, so a device with several modules corresponds to several entries. Vendor modules (`cisco_device`, for example) stay outside the reference: the list is open and extending it is a property of the deployment.
- Behavioural review fixes of the reference: the `logs.enabled=false` opt-out excludes the container before `loki.source.docker` rather than line by line in the tailer; the mandatory `metrics.port`, `blackbox.port` and `metrics.job` are checked by a fail-closed presence keep -- a container with no exposed TCP ports no longer passes `keepequal` and is not scraped on port 80, and a missing `metrics.job` drops the target instead of substituting the name of the scrape component; an snmp entry without `name` takes its name from `address` instead of failing the whole exporter.
- The database domain: series carry `host`; series identity is `database.instance`, then the global `instance`, then `secret-id` (fallback); `database.name`/`user`/`sslmode` are declared inventory-only (the sole source of connection parameters is `.dsn`). Overlay [070](alloy-optional/070_host-metrics.alloy) adds the `host`/`collector` provenance to `node_*` series; snmp series carry a `device` label holding the device name.
- The `mixed-v1` profile: the JSON and logfmt stages were made mutually exclusive (a line cannot pass both parsers), and the stages gained `pipeline_name`.
- Section [13.5](docs/manifest.md#135-trust-in-labels) was extended: the no-SSRF guarantee is limited to the metrics/database domains, while `blackbox.address` and the unauthenticated OTLP receiver are documented as exceptions with recommendations; documented the semantics of an empty label value, the `version`/`stream-policy` reservation, the behaviour when the collector is recreated (positions/WAL), the Loki requirements for structured metadata, and backend authentication (Mimir/Grafana Cloud).
- New static gates: coverage of the domain label tables ([10](docs/manifest.md#10-domains)) against the configuration (the `LABELS_UNREAD` table), `host`/`collector` provenance across every series path, paired collisions of overlay files, protection against phantom entries in the module gap tables (the dead `cisco_device` entry was removed); `tools/materialize` now clears stale files out of a reused directory.
- Fixed section [14](docs/manifest.md#14-reference-implementation) about multiple networks: a container attached to several Docker networks does not produce duplicate targets -- the `discovery.docker` default `match_first_network = true` picks the first network in alphabetical order of names; the real risk is that the chosen network may be unreachable for Alloy (`up == 0`), while logs do not depend on reachability. Log deduplication by container ID is pinned by an e2e gate: a container with several exposed ports is read exactly once.
- Fixed the YAML anchors example in [15.1](docs/manifest.md#151-docker-compose-anchors): the top-level anchor key was renamed to `x-3ops-discovery-common` -- compose rejects a file with an unknown top-level key outright. The rule is now pinned in both directions (a top-level key requires `x-`, a key inside `labels:` must stay reverse-DNS) and covered by a new static gate over the section 15 examples (YAML parsing and key shape checks; `docker compose config` is not run in the static set).
- Added a release artifact: `uv run nox -s release` builds a reproducible `tar.gz` (the contract, the reference configuration, the overlay files, a deployment README) plus `SHA256SUMS`, published by a workflow on a `vX.Y.Z` tag. The version comes from the manifest header alone and the tag must match it, while the manifest status governs the kind of release: as long as the specification says `Draft`, only snapshot tags such as `v0.2.0-snapshot.1` are accepted (published as pre-releases) -- a draft must not occupy the final number under which a reader expects the finished contract, and the tag suffix reaches the archive name so two snapshots of one version cannot collide; the contents are enumerated by `git ls-files` (the first build, which copied whole directories, swept an untracked scratch directory into the archive); the `.alloy` set in the archive is checked against the set `alloy_check` validates, and a rebuild must produce the same sha256.
- The specification gained an English translation ([`docs/manifest.md`](docs/manifest.md), the README and this changelog). The translation is declared non-normative -- the anchor gates read the Russian originals alone -- and is bound to its original by a structural isomorphism gate: heading levels, section numbers, code fence languages, list items and table rows must match one for one (the single deliberate divergence lives in the `TRANSLATION_EXTRA_TABLE_ROWS` table). A separate check catches a section number that spilled outside its link: `[§1](...#1-purpose)0.x` reads as §10.x but points at §1, and the ordinary link gate cannot see it because the anchor is valid.
- Implemented the validator announced by [10.6.1](docs/manifest.md#1061-snmp-auth) (`tools/snmp_fixtures.validate_auths`): the SNMP version from the `{2, 3}` allowlist, the fields required by `security_level`, and the `security_level`/`auth_protocol`/`priv_protocol` enums. The enums were moved into the manifest from an internal design document (the dangling "file schema" reference was removed), and it was clarified that the version is given as a number (`version: 2` means v2c) rather than the string `v2c`/`v3`.
- The reference no longer follows redirects: `follow_redirects = false` in all thirteen `prometheus.scrape` blocks (the metrics, database and blackbox domains plus the [037](alloy-optional/037_snmp.alloy)/[070](alloy-optional/070_host-metrics.alloy)/[075](alloy-optional/075_container-metrics.alloy) overlays). The [13.5](docs/manifest.md#135-trust-in-labels) promise that SSRF is excluded for metrics and database held for the first request only: the address is built from Docker metadata, but the scrape response is just as untrusted an input, and a container answering `302` with a link-local address would send the next request there on the collector's behalf. The wording of 13.5 now matches (two conditions carry the guarantee, not one), and a new gate demands the setting from EVERY scrape block, including the four database blocks nested inside a `foreach` that a line-anchored scan does not see.
- The comments in the shipped config were brought back in line with it, and the whole class of drift was closed. `94d795a` corrected the refuted claim about duplicate multi-network targets in the manifest, in [040](alloy/040_logs.alloy) and in the e2e compose, but left it standing in [020](alloy/020_metrics.alloy) and [030](alloy/030_database.alloy), where a reader of the reference meets it first; the [080](alloy-optional/080_host-logs.alloy) overlay claimed journal fields stay in the line, whereas `format_as_json = false` drops them outright (`_SYSTEMD_UNIT`, `PRIORITY`, `_PID`), so host logs cannot be attributed to a unit; [070](alloy-optional/070_host-metrics.alloy) and 080 cited "spec 5.4", a section of an internal document the recipient of the archive never sees. A comment cannot be checked for truth, but its citation can: a new gate resolves every reference against a real manifest section, forbids references to foreign documents, and catches spellings the strict pattern does not parse -- otherwise `manifest sec. 8.4` would read as a promise nobody checks.
- The demo sandbox `nox -s demo` hands over as an example was hardened: the anonymous Grafana was lowered from `Admin` to `Editor` (managing data sources is an Admin-only capability in Grafana OSS, so an anonymous Admin could add one pointing at any URL and read the answer -- an SSRF foothold inside the telemetry network reached with no credentials at all; Editor keeps Explore, which a Viewer does not have), and secret files are created with mode `0600` in both utilities (`tools/secret_files.write_secret`) -- the one clause of [9](docs/manifest.md#9-secret-contract) no gate covered, and it outlives the sandbox: `nox -s demo` leaves `.demo/secrets/*.dsn` in the working tree. [13.3](docs/manifest.md#133-docker-socket) was clarified: the requirement that Alloy not be reachable from an untrusted Docker network cannot be met in full, because scraping a container means sharing a network with it and splitting networks does not help (`discovery.docker` takes only the alphabetically first one) -- untrusted workloads are separated by a collector of their own, not by a network of the same one.
- The secret-redaction promise in [9](docs/manifest.md#9-secret-contract) was narrowed: `is_secret = true` guarantees redaction in the Alloy API and in component exports, but NOT in configuration-load error messages -- when the declared type and the file content disagree, Alloy quotes a fragment of the value it read (the `host:port` of another database), and no configuration changes that, it is Alloy behaviour. The consequence became a separate warning in [13](docs/manifest.md#13-security-requirements): the collector's own logs are sensitive, the reference collects them deliberately (observing the collector), and with a less trusted backend collection is switched off by an explicit `logs.enabled=false` on the Alloy container. Documenting a limit is half the work, so the half that still holds is now pinned by an e2e gate: no per-run generated password appears in Loki, and the search runs over Alloy's own live log stream (mutation-checked -- substituting a substring known to be present fails the test).
- Every hardcoded list in the static gates gained a completeness check against its source of truth -- the pattern that makes a gate catch drift inside the list while staying blind to whatever never entered it. Five instances: the set of sections with labels tables is derived from the manifest itself (the ipmi [10.7.1](docs/manifest.md#1071-labels) was written past the hand-kept tuple -- five documented labels neither direction of the check ever saw; they are now in `LABELS_UNREAD` with reasons, and `manifest_doc` learned to read a labels list from a ```text block as well, because converting 10.7.1 into a table would have meant inventing a mandatory column the contract never stated); the provenance file set is computed from the glob minus an explicit `NOT_SERIES_PATHS` table whose every entry is checked in both directions; the `metrics.type` allowlist is bound to [10.1.1](docs/manifest.md#1011-labels), the one domain type with nothing on the other end. Profile keep-regex parsing became strict: `regex.strip("()?")` returned the same thing for `(fast-v1)` and `(fast-v1)?`, and that `?` is the entire difference between a filter serving marked targets and one that also swallows every unmarked one; a profile pair copied with the marker left on would have scraped every default target twice and passed every gate. The default marker is now checked against the manifest, and e2e covers the reverse direction too (an unmarked target reaches neither fast nor slow). Finally `extension_point_targets()` was extended to `.output`, and an overlay may only consume exports documented in [14.4](docs/manifest.md#144-extension-points) -- existing in base is weaker than being published, and the export kind is compared as well.
- The normative contradictions where the text demanded the impossible while the reference behaved correctly were resolved. [8.4](docs/manifest.md#84-database-profiles) claimed a profile outside the allowlist drops the target "as in every other domain", whereas [10.3.4](docs/manifest.md#1034-unknown-profile) requires that logs never be lost and `raw-v1` apply; reading it so that the more specific rule wins rescued the meaning, but a normative document must not need rescuing -- both statements (8.4 and [11](docs/manifest.md#11-validation-rules)) now name the exception explicitly, pinned by a gate. [5](docs/manifest.md#5-global-labels) declared `enabled` mandatory for five domains including otel and ipmi, whose labels 10.5 and 10.7 declare declarative: the requirement was unmeetable for two domains out of five, and 11 inherited the defect. Declaring and reading are now separated: `enabled` governs participation in metrics/database/blackbox, while for otel and ipmi it stays an inventory declaration of intent -- the contract cannot require an implementation to read what it has no way of reading.
- The contract that existed only in code was written down. The scrape cadence of the database domain was specified NOWHERE -- neither in the manifest nor in the configuration: the four blocks silently inherited the Alloy default, so a contract value was in effect defined by the version of a third-party product and would have moved when it was updated. `interval: 60s`, `timeout: 10s` are now fixed in [8.4](docs/manifest.md#84-database-profiles) and stated explicitly (the same values that were in force -- behaviour did not change), and a gate demands explicit `scrape_interval`/`scrape_timeout` from every block, the [070](alloy-optional/070_host-metrics.alloy)/[075](alloy-optional/075_container-metrics.alloy) overlays included. The rule "an empty mandatory label drops the target" moved from the reference's comments into [11](docs/manifest.md#11-validation-rules): the previous wording -- an empty value equals an absent label and the default applies -- is vacuous for mandatory labels, which have no default, and a second implementer would have let the target through. Series identity is documented by a table in [6.1](docs/manifest.md#61-labels-added-by-alloy) for all four domains: the `job` constants of the blackbox and snmp domains and the `snmp_profile` label (which leaked into the contract from a test anchor -- documented rather than removed, since dashboards may already group by it) are now checked against the configuration. The blackbox domain ignoring the global `instance` is declared a deliberate exception: for a probe, the instance is the probe target itself.
- An editorial pass over the residual textual defects of the manifest, seven places. The OTLP ports `4317`/`4318` were not mentioned at all -- they are now fixed in [10.5](docs/manifest.md#105-domain-otel) together with the reason they are NOT parameterized by an environment variable (an address senders know in advance is not a deployment value). [10.3.6](docs/manifest.md#1036-examples) described the `mixed-v1` heuristics with "may" and said nothing about the mutual exclusion of the branches that the reference implements: without it the result would depend on stage order, which is now normative and pinned by a gate. [14](docs/manifest.md#14-reference-implementation) gained an Alloy version policy: no compatibility range is declared deliberately -- exactly one version has honestly been verified, and no lower bound is given because `foreach` is experimental; it also states that the contract offers no configuration free of experimental features and how to get one (drop 030 along with the database domain). The format of `ru.3ops.discovery.version` is fixed (`^\d+\.\d+$`) along with the behaviour on an unsupported version. `logs.enabled` is declared the only fail-OPEN check in the contract, with the reason for the direction of failure. The format of `blackbox.address` is defined as a bare host, and the example in [10.4.1](docs/manifest.md#1041-labels) that read as permission to write `host:port` into the label was rewritten. [6.1](docs/manifest.md#61-labels-added-by-alloy) now names the log-side `log_profile`/`source`/`service_name` and points at 6.2 as the normative source for logs.
