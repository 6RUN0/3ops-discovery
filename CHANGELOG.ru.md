# Changelog

Все заметные изменения спецификации 3ops Discovery фиксируются в этом файле.

## 0.2.0 — Draft

- Docker stdout/stderr собираются по умолчанию для всех контейнеров.
- `ru.3ops.discovery.logs.enabled=false` используется как явный opt-out.
- `ru.3ops.discovery.logs.profile` теперь обозначает имя заранее определённого и версионированного pipeline-профиля.
- Профили вида `json,logfmt,raw` запрещены: label не является языком описания стадий.
- `raw` считается неявным fallback для любого профиля, если стадия парсинга не смогла разобрать строку.
- Добавлены базовые профили `raw-v1`, `generic-json-v1`, `generic-logfmt-v1`, `mixed-v1`.
- Добавлены правила версионирования log pipelines.
- Свободные значения `interval`/`timeout` в labels заменены версионированными профилями `metrics.profile`, `database.profile`, `blackbox.profile` из allowlist.
- Требование версии в имени распространено на все профили, не только на log-профили.
- Secret contract обобщён на домены `snmp` и `ipmi` (доменные суффиксы файлов секретов).
- Задокументировано исключение домена `logs` из требования `ru.3ops.discovery.enabled`.
- Референсная конфигурация Alloy вынесена в каталог `alloy/` (файлы с числовыми префиксами; единая точка интеграции с backend — [`090_outputs.alloy`](alloy/090_outputs.alloy)).
- Определён контракт переменных окружения `RU_3OPS_DISCOVERY_*` для deployment-специфичных параметров референсной конфигурации.
- Поля, извлечённые из содержимого логов, отправляются только в structured metadata, не в stream labels.
- Пространство `secret-id` задокументировано как единый trust domain хоста; привязка секрета к identity контейнера объявлена out of scope.
- Добавлен раздел [13.5](docs/manifest.ru.md#135-доверие-к-labels) о границах доверия к labels.
- В референсной конфигурации реализованы relabel-валидации `path`/`scheme`/`profile` и схлопывание port fan-out для metrics и database.
- Домен database расширен на типы `mysql`/`mariadb`, `redis`, `mongodb`; серии всех exporter'ов несут provenance-labels (`environment`/`team`/`container`/`compose_*`/`collector`, синтезированные `job`/`instance`).
- Для redis формат секрета — `host:port` в `.dsn` плюс пароль в отдельном файле `<secret-id>.redispass` (аргумент `redis_addr` не принимает секрет).
- Добавлены multiline log-профили `python-stacktrace-v1` и `java-stacktrace-v1`: многострочные traceback склеиваются в одну запись.
- Введён overlay-каталог `alloy-optional/` и первый opt-in файл [`060_otel.alloy`](alloy-optional/060_otel.alloy) (OTLP receiver: метрики в `prometheus.remote_write`, логи в `loki.write` через allowlist-processor).
- Задокументирована модель кастомизации: extension points базы (раздел [14.4](docs/manifest.ru.md#144-extension-points)), опциональные файлы ([14.5](docs/manifest.ru.md#145-опциональные-файлы)), соглашения против коллизий имён.
- Добавлены таблицы стандартных портов БД ([10.2](docs/manifest.ru.md#102-domain-database)) и форматов секрет-файла по типам ([9](docs/manifest.ru.md#9-secret-contract)); зафиксировано исключение провенанса для OTLP-пути.
- Уточнено, что `database.type` обозначает wire-протокол, а не вендора: протокол-совместимые сборки (Percona Server for MySQL/MongoDB, XtraDB Cluster) метятся базовым типом `mysql`/`mongodb` без отдельного типа.
- Добавлен опциональный файл host-метрик [`070_host-metrics.alloy`](alloy-optional/070_host-metrics.alloy) (`prometheus.exporter.unix`, серии `node_*`); rootfs/procfs/sysfs-пути параметризуются `RU_3OPS_DISCOVERY_HOST_ROOTFS_PATH`/`_PROCFS_PATH`/`_SYSFS_PATH`.
- Добавлен опциональный файл host-логов [`080_host-logs.alloy`](alloy-optional/080_host-logs.alloy) (`loki.source.journal` из systemd journal → `loki.write`) со статическими labels `host`/`collector`/`source`.
- Реализован домен blackbox ([`035_blackbox.alloy`](alloy/035_blackbox.alloy)): HTTP-пробы по Docker-labels `ru.3ops.discovery.blackbox.*` через `prometheus.exporter.blackbox` (референс-модуль `http_2xx`, профиль `normal-v1`).
- Домен snmp ([§8.5](docs/manifest.ru.md#85-snmp-профили)/[§10.6](docs/manifest.ru.md#106-domain-snmp)/[§10.6.1](docs/manifest.ru.md#1061-snmp-auth)/[§14.5](docs/manifest.ru.md#145-опциональные-файлы)): файловый провайдер устройств, auth-модель v2c/v3 (authPriv), opt-in overlay [`037_snmp.alloy`](alloy-optional/037_snmp.alloy), static-гейты и e2e с живым Net-SNMP агентом.
- Уточнён домен ipmi ([§10.7](docs/manifest.ru.md#107-domain-ipmi)): у Alloy нет нативного IPMI-компонента, поэтому домен переформулирован как частный случай `metrics` — скрейп Prometheus-endpoint внешнего `ipmi_exporter`; labels и суффикс секрета `.ipmi` сохранены (семантика контракта не изменилась).
- Добавлен опциональный файл per-container метрик [`075_container-metrics.alloy`](alloy-optional/075_container-metrics.alloy) (`prometheus.exporter.cadvisor`, серии `container_cpu_*`/`container_memory_*`/`container_network_*`): Docker API через socket-proxy (реюз `RU_3OPS_DISCOVERY_DOCKER_HOST`), провенанс [§6.1](docs/manifest.ru.md#61-labels-добавляемые-alloy) из allowlisted container-labels (`name` → `container`, сырые `container_label_*` отбрасываются), root-cgroup-статистика отключена; требует host cgroup namespace (`cgroup: host`, привилегированный overlay [§14.3](docs/manifest.ru.md#143-кастомизация-референсной-конфигурации)).
- Референсная конфигурация реализует все базовые scrape-профили [§8.2](docs/manifest.ru.md#82-scrape-профили) (`fast-v1`/`normal-v1`/`slow-v1`) для доменов metrics и blackbox: общий relabel несёт валидацию и провенанс, тонкая пара фильтр+scrape на профиль — маршрутизацию; имена профильных компонентов выводятся из полного имени профиля.
- Домен blackbox расширен модулями `tcp_connect` и `icmp` с покомпонентной композицией цели пробы (URL / `host:port` / голый host); сериям проб добавлен label `module`; ICMP-пробы работают без дополнительных привилегий контейнера, для hardened-сред задокументирован выход.
- Добавлен модуль `tls_connect` — все четыре обещанных семейства проб (HTTP, TCP, ICMP, TLS) отгружены референсом; модуль проверяет TLS handshake и отдаёт метрики срока действия сертификата, верификация цепочки доверия задокументирована как кастомизация окружения (`ca_file`).
- Реализованы database-профили [§8.4](docs/manifest.ru.md#84-database-профили) (`basic-v1`/`standard-v1`/`extended-v1`): профиль управляет объёмом сбора экспортёра (набором коллекторов), а не каденцией скрейпа; `standard-v1` соответствует дефолтам экспортёров, значение вне allowlist отбрасывает цель (fail-closed); маппинг профилей на коллекторы по типам СУБД задокументирован в [§8.4](docs/manifest.ru.md#84-database-профили).
- В allowlist snmp-модулей ([§10.6](docs/manifest.ru.md#106-domain-snmp)) добавлен `system` (идентичность и аптайм безагентных устройств: `sysUpTime`, `sysName`); одна запись device-файла — один модуль, устройству с несколькими модулями соответствует несколько записей. Vendor-модули (например `cisco_device`) остаются за пределами референса: список открытый, расширение — свойство деплоя.
- Ревью-фиксы референса (поведенческие): opt-out `logs.enabled=false` исключает контейнер до `loki.source.docker`, а не построчно в тейлере; обязательные `metrics.port`, `blackbox.port` и `metrics.job` проверяются fail-closed presence-keep — контейнер без экспонированных TCP-портов больше не проходит `keepequal` и не скрейпится на порт 80, а отсутствие `metrics.job` отбрасывает target вместо подстановки имени scrape-компонента; snmp-запись без `name` получает имя из `address` вместо отказа всего экспортёра.
- Домен database: серии несут `host`; идентичность серии — `database.instance`, затем глобальный `instance`, затем `secret-id` (fallback); `database.name`/`user`/`sslmode` объявлены инвентарными (источник параметров подключения — только `.dsn`). Overlay [070](alloy-optional/070_host-metrics.alloy) добавляет провенанс `host`/`collector` к сериям `node_*`; snmp-серии несут label `device` с именем устройства.
- Профиль `mixed-v1`: JSON- и logfmt-стадии сделаны взаимоисключающими (строка не проходит оба парсера), стадиям добавлены `pipeline_name`.
- Расширен [§13.5](docs/manifest.ru.md#135-доверие-к-labels): гарантия отсутствия SSRF ограничена доменами metrics/database, `blackbox.address` и неаутентифицированный OTLP-приёмник задокументированы как исключения с рекомендациями; задокументированы семантика пустого значения label, резерв `version`/`stream-policy`, поведение при пересоздании коллектора (positions/WAL), требования Loki к structured metadata и аутентификация backend'ов (Mimir/Grafana Cloud).
- Новые статические гейты: покрытие таблиц labels доменов ([§10](docs/manifest.ru.md#10-домены)) против конфига (таблица `LABELS_UNREAD`), провенанс `host`/`collector` по всем путям серий, парные коллизии overlay-файлов, защита от фантомных записей gap-таблиц модулей (удалена мёртвая запись `cisco_device`); `tools/materialize` очищает переиспользуемый каталог от устаревших файлов.
- Исправлен [§14](docs/manifest.ru.md#14-reference-implementation) про мультисеть: контейнер в нескольких Docker-сетях не даёт дублирующихся targets — дефолт `discovery.docker` `match_first_network = true` выбирает первую сеть по алфавиту имён; реальный риск — недостижимость выбранной сети для Alloy (`up == 0`), логи от достижимости не зависят. Дедупликация логов по container ID закреплена e2e-гейтом: контейнер с несколькими exposed-портами читается ровно один раз.
- Исправлен пример YAML anchors в [§15.1](docs/manifest.ru.md#151-docker-compose-anchors): anchor-ключ верхнего уровня переименован в `x-3ops-discovery-common` — compose отвергает файл с неизвестным top-level ключом целиком. Правило зафиксировано в обе стороны (top-level требует `x-`, ключ внутри `labels:` обязан оставаться reverse-DNS) и закрыто новым статическим гейтом на примеры раздела 15 (разбор YAML и проверка формы ключей; `docker compose config` в статическом наборе не запускается).
- Добавлен релизный артефакт: `uv run nox -s release` собирает воспроизводимый `tar.gz` (контракт, референсная конфигурация, overlay-файлы, deployment-README) и `SHA256SUMS`, публикация — workflow по тегу `vX.Y.Z`. Версия берётся только из шапки манифеста, тег обязан ей соответствовать, а статус манифеста управляет типом релиза: пока спецификация в статусе `Draft`, допустимы только снапшот-теги вида `v0.2.0-snapshot.1` (публикуются как pre-release) — черновик не занимает финальный номер, под которым читатель ждёт готовый контракт, и суффикс тега попадает в имя архива, поэтому два снапшота одной версии не сталкиваются; содержимое перечисляет `git ls-files` (первая сборка через копирование каталогов утащила в архив неотслеживаемый служебный каталог); набор `.alloy` в архиве сверяется с набором, который валидирует `alloy_check`, а повторная сборка обязана давать тот же sha256.
- Спецификация получила англоязычный перевод ([`docs/manifest.md`](docs/manifest.md), README и changelog). Перевод объявлен ненормативным — анкерные гейты читают только русские оригиналы — и связан с оригиналом гейтом структурного изоморфизма: уровни заголовков, номера разделов, языки код-блоков, пункты списков и строки таблиц обязаны совпадать один в один (единственное осознанное расхождение — таблица `TRANSLATION_EXTRA_TABLE_ROWS`). Отдельная проверка ловит номер раздела, «утёкший» за пределы ссылки: `[§1](…#1-назначение)0.x` читается как §10.x, а ведёт на §1, и обычный гейт ссылок этого не видит — якорь валиден.
- Реализован объявленный [§10.6.1](docs/manifest.ru.md#1061-snmp-auth) валидатор auth-фикстуры (`tools/snmp_fixtures.validate_auths`): версия SNMP из allowlist `{2, 3}`, обязательные поля по `security_level`, enum-ы `security_level`/`auth_protocol`/`priv_protocol`. Enum-ы перенесены в манифест из внутреннего дизайн-документа (висячая ссылка «Схема файлов» удалена), уточнено, что версия задаётся числом (`version: 2` = v2c), а не строкой `v2c`/`v3`.
- Референс перестал следовать редиректам: `follow_redirects = false` во всех тринадцати `prometheus.scrape` (домены metrics, database, blackbox и overlay [037](alloy-optional/037_snmp.alloy)/[070](alloy-optional/070_host-metrics.alloy)/[075](alloy-optional/075_container-metrics.alloy)). Обещание [§13.5](docs/manifest.ru.md#135-доверие-к-labels) «для metrics и database SSRF исключён» до этого держалось только на первом запросе: адрес строится из метаданных Docker, но ответ scrape — такой же недоверенный вход, и контейнер, ответивший `302` на link-local адрес, увёл бы туда следующий запрос от имени коллектора. Формулировка §13.5 приведена в соответствие (гарантию дают два условия, а не одно), новый гейт требует флаг от КАЖДОГО блока scrape, включая четыре вложенных в `foreach` блока database, которые построчный поиск не видит.
- Приведены в соответствие комментарии поставляемого конфига и закрыт весь класс расхождения. `94d795a` исправил опровергнутое утверждение про дубликаты targets в мультисети в манифесте, [040](alloy/040_logs.alloy) и e2e-compose, но оставил его в [020](alloy/020_metrics.alloy) и [030](alloy/030_database.alloy) — там, где читатель референса встречает его первым; overlay [080](alloy-optional/080_host-logs.alloy) утверждал, что поля journal остаются в строке, тогда как при `format_as_json = false` теряются целиком (`_SYSTEMD_UNIT`, `PRIORITY`, `_PID`), то есть host-логи нельзя атрибутировать юниту; [070](alloy-optional/070_host-metrics.alloy) и 080 ссылались на «spec 5.4» — раздел внутреннего документа, которого получатель архива никогда не увидит. Истинность комментария проверить нельзя, ссылку — можно: новый гейт резолвит каждую ссылку на раздел манифеста, запрещает ссылки на посторонние документы и ловит написания, которые строгий шаблон не разбирает, — иначе `manifest sec. 8.4` читался бы как обещание, которое никто не проверяет.
- Ужесточена демо-песочница, которую `nox -s demo` отдаёт как образец: анонимная Grafana понижена с `Admin` до `Editor` (управление datasource — Admin-only возможность Grafana OSS, то есть анонимный Admin мог завести datasource на произвольный URL и прочитать ответ — плацдарм для SSRF внутрь телеметрической сети без единого пароля; Editor сохраняет Explore, которого у Viewer нет), файлы секретов создаются с режимом `0600` в обеих утилитах (`tools/secret_files.write_secret`) — единственный пункт [§9](docs/manifest.ru.md#9-secret-contract), не покрытый ни одним гейтом, и он переживает песочницу: `nox -s demo` оставляет `.demo/secrets/*.dsn` в рабочем дереве. Уточнён [§13.3](docs/manifest.ru.md#133-docker-socket): требование «Alloy не должен быть доступен из недоверенной Docker-сети» невыполнимо в полной мере, потому что скрейп контейнера означает общую с ним сеть, а разделение сетей не помогает (`discovery.docker` берёт только первую по алфавиту) — недоверенные нагрузки отделяются отдельным коллектором, а не отдельной сетью того же самого.
- Сужено обещание редакции секретов в [§9](docs/manifest.ru.md#9-secret-contract): `is_secret = true` гарантирует редакцию в API Alloy и экспортах компонентов, но НЕ в сообщениях об ошибках загрузки конфигурации — при несовпадении типа и содержимого файла Alloy цитирует фрагмент прочитанного значения (`host:port` чужой БД), и конфигурацией это не меняется, это поведение Alloy. Следствие вынесено в [§13](docs/manifest.ru.md#13-security-requirements) отдельным предупреждением: логи самого коллектора чувствительны, референс собирает их осознанно (наблюдаемость коллектора), а при менее доверенном backend'е сбор отключается явным `logs.enabled=false` на контейнере Alloy. Документировать границу — половина работы, поэтому уцелевшая половина обещания закрыта e2e-гейтом: ни один сгенерированный на прогон пароль не появляется в Loki, причём поиск идёт по живому потоку логов самого Alloy (проверено мутацией — подстановка заведомо присутствующей подстроки роняет тест).
- Каждый захардкоженный список в статических гейтах получил проверку полноты против источника истины — паттерн, из-за которого гейт ловит расхождение внутри списка и слеп к тому, что в список не попало. Пять инстансов: перечень разделов с таблицами labels выводится из самого манифеста (§10.7.1 домена ipmi был написан мимо ручного кортежа — пять задокументированных labels, которых не видела ни одна из двух сторон проверки; они внесены в `LABELS_UNREAD` с причинами, а `manifest_doc` научился читать список labels и из ```text-блока: перевод §10.7.1 в таблицу потребовал бы выдумать колонку «Обязательный», которой контракт никогда не задавал); набор файлов с провенансом вычисляется из glob за вычетом явной таблицы `NOT_SERIES_PATHS`, каждая запись которой проверяется в обе стороны; allowlist `metrics.type` сверяется с [§10.1.1](docs/manifest.ru.md#1011-labels) — единственный доменный тип, у которого не было пары. Разбор профильного keep-регекса стал строгим: `regex.strip("()?")` возвращал одно и то же для `(fast-v1)` и `(fast-v1)?`, а этот `?` — вся разница между фильтром для помеченных целей и фильтром, который вдобавок забирает все непомеченные; скопированная с маркером профильная пара скрейпила бы каждую цель по умолчанию дважды и прошла бы все гейты. Теперь маркер по умолчанию сверяется с манифестом, а e2e проверяет и обратное направление (непомеченная цель не попадает в fast/slow). Наконец, `extension_point_targets()` расширен на `.output`, а overlay обязан ссылаться только на экспорты, задокументированные в [§14.4](docs/manifest.ru.md#144-extension-points), — существование компонента в базе слабее, чем публичность: вид экспорта тоже сверяется.
- Устранены нормативные противоречия, где текст требовал невыполнимого, а референс вёл себя правильно. [§8.4](docs/manifest.ru.md#84-database-профили) утверждал, что профиль вне allowlist отбрасывает цель «как и в остальных доменах», тогда как [§10.3.4](docs/manifest.ru.md#1034-неизвестный-профиль) требует не терять логи и применить `raw-v1`; чтение «более частное правило побеждает» смысл спасало, но нормативный документ спасать не должны — обе формулировки (§8.4 и [§11](docs/manifest.ru.md#11-validation-rules)) теперь называют исключение явно, и это закрыто гейтом. [§5](docs/manifest.ru.md#5-глобальные-labels) объявлял `enabled` обязательным для пяти доменов, включая otel и ipmi, чьи labels §10.5 и §10.7 объявляют декларативными: требование было невыполнимо для двух доменов из пяти, а §11 наследовал дефект. Объявление и чтение разведены: `enabled` управляет участием в metrics/database/blackbox, а для otel и ipmi остаётся инвентарным объявлением намерения — требовать от реализации чтения того, что прочитать нечем, контракт не может.
- Записан в контракт тот, что до сих пор существовал только в коде. Каденция скрейпа домена database не была задана НИГДЕ — ни в манифесте, ни в конфигурации: четыре блока молча наследовали дефолт Alloy, то есть контрактная величина де-факто определялась версией стороннего продукта и сдвинулась бы при его обновлении. Теперь `interval: 60s`, `timeout: 10s` зафиксированы в [§8.4](docs/manifest.ru.md#84-database-профили) и заданы явно (те же значения, что действовали, — поведение не изменилось), а гейт требует явных `scrape_interval`/`scrape_timeout` от каждого блока, включая overlay [070](alloy-optional/070_host-metrics.alloy)/[075](alloy-optional/075_container-metrics.alloy). Правило «пустой обязательный label = target отбрасывается» перенесено из комментариев референса в [§11](docs/manifest.ru.md#11-validation-rules): прежняя формулировка «пустое значение = отсутствие label, действует default» для обязательных labels вакуумна — default'а у них нет, и вторая реализация цель бы пропустила. Идентичность серий задокументирована таблицей в [§6.1](docs/manifest.ru.md#61-labels-добавляемые-alloy) для всех четырёх доменов: константы `job` доменов blackbox/snmp и label `snmp_profile` (протёкший в контракт из тестового якоря — задокументирован, а не удалён: на нём могут висеть чужие дашборды) теперь сверяются с конфигурацией. Игнорирование глобального `instance` доменом blackbox объявлено осознанным исключением: для пробы instance'ом является сама цель.
- Редакторский проход по остаточным текстовым дефектам манифеста, семь мест. Порты OTLP `4317`/`4318` не упоминались вовсе — теперь зафиксированы в [§10.5](docs/manifest.ru.md#105-domain-otel) вместе с причиной, по которой они НЕ параметризуются переменной окружения (адрес, который отправители знают заранее, — не deployment-величина). [§10.3.6](docs/manifest.ru.md#1036-примеры) описывала эвристики `mixed-v1` через «может» и умалчивала о взаимном исключении ветвей, которое референс реализует: без него результат зависел бы от порядка стадий, и это теперь нормативно и закрыто гейтом. [§14](docs/manifest.ru.md#14-reference-implementation) получила политику версии Alloy: диапазон совместимости не объявляется намеренно — честно проверена ровно одна версия, а нижняя граница не указывается, потому что `foreach` экспериментален; отдельно сказано, что конфигурации без экспериментальных возможностей контракт не предлагает и как её получить (исключить 030 вместе с доменом database). Формат `ru.3ops.discovery.version` зафиксирован (`^\d+\.\d+$`) вместе с поведением при неподдерживаемой версии. `logs.enabled` объявлен единственной fail-OPEN проверкой контракта — с обоснованием направления отказа. Формат `blackbox.address` определён как голый хост, и пример в [§10.4.1](docs/manifest.ru.md#1041-labels), читавшийся как разрешение писать `host:port` в label, переписан. [§6.1](docs/manifest.ru.md#61-labels-добавляемые-alloy) теперь называет логовые `log_profile`/`source`/`service_name` и указывает на §6.2 как на нормативный источник для логов.
- Доспецифицированы log-профили. Наборы извлекаемых полей не были заданы и расходились в самом референсе: `generic-json-v1` извлекал `level`/`trace_id`/`request_id`, а `generic-logfmt-v1` — то же плюс `status`, и тот же раскол был в двух ветвях `mixed-v1`. Профили одного семейства различаются форматом входа, а не составом извлекаемого, поэтому наборы выровнены (`status` добавлен в JSON-ветви) и зафиксированы таблицей в [§8.3](docs/manifest.ru.md#83-log-профили): имя профиля — обещание, что две независимые реализации дают одинаковые метаданные. Гейт сверяет обе половины — что извлекает парсер И что объявлено в structured metadata: проверка одной только декларации приняла бы за согласие поле, которое присутствует в каждой записи и всегда пусто. Предпосылка multiline-профилей записана явно: якорь firstline требует ISO-8601-префикса, и приложение без него не даёт НИ ОДНОЙ строки-начала — весь поток склеивается в блоки по `max_lines`, границы которых к содержимому отношения не имеют; `max_lines = 128` теперь задан явно, а не унаследован. e2e этот случай поймать не может — мини-приложение печатает таймстампы.
